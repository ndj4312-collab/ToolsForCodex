# Agentic Intel — repository packaging context

## Authority

This reference packages the already-established Notion semantic owner **Agentic Research-to-Application** (`agentic-research-to-application`) into ToolsForCodex. It must not reinterpret or replace that owner.

Repository status remains `IMPLEMENTED_UNVERIFIED` until independent eval plus registered runtime discovery/invocation pass.

## Required semantic invariants

Preserve:
- explicit `/agentic-intel` and semantic external-intelligence → agentic-system-application triggering;
- negative scope for summaries, generic lookup, non-agentic work, ingest-owned work, pure idealize, and narrower exact owners;
- explicit `notion | notion+web` evidence-plane declaration;
- frozen coverage mode and denominator semantics;
- source-native evidence and SourceRecords;
- explicit conflicts and unknowns;
- recursive primitive decomposition;
- bounded adjacent search with decision-delta saturation;
- evidence graph: `SOURCE → FINDING → SYNTHESIS → REQUIREMENT → DECISION → IMPLEMENTATION → TEST`;
- current-surface mapping and dependency closure;
- brainstorming, red-team, convergence, and candidate classification;
- `REUSE → ADAPT → COMPOSE → CREATE` before net-new capability creation;
- downstream realization through current exact owners;
- independent evaluator / champion-challenger requirements;
- earliest-causal-stage reopen on new primitives, dependencies, stale state, or failed validation;
- evidence-bounded status semantics;
- no automatic canon/endurance promotion and no remote-push authority.

## Scholarly efficacy mode

When the claim is that a method improves performance, repositories, blogs, or implementation examples are not sufficient efficacy evidence.

Prefer recent qualifying peer-reviewed research with accessible abstract, methods, and results. Extract intervention, baseline/control, measured result, statistical support/effect size when available, environment, and engineering translation.

Non-scholarly sources may establish implementation mechanics, not scientific efficacy.

## Benefit thresholds

Candidate improvements should normally justify themselves through at least one:
- 10–15%+ reduction in human intervention or cognitive burden;
- 25%+ relative quality improvement on a predeclared metric;
- if burden increases, >70% relative productivity improvement may override it.

Numerical lift alone is insufficient. The accepted change should create enduring reusable cross-agent/cross-skill capability, workflow, methodology, deterministic primitive, evaluator, or runtime capability.

If the planned search scope is complete and no material candidate passes a tunable benefit threshold, a run-scoped empirical threshold may be derived from valid comparable observed scores. Never self-amend scholarly eligibility, functional nonduplication, enduring-value, remote-push prohibition, safety/authority, or runtime-proof requirements. No comparable data means `INSUFFICIENT_COMPARABLE_EVIDENCE`.

## Verification sequence

Repository packaging evidence is not runtime acceptance.

1. package files;
2. register manifest/index/router;
3. static remote read-back;
4. with-skill vs baseline evals;
5. registered `find_skills`/`load_skill` or equivalent discovery/invocation;
6. intended-client observed behavior;
7. independent audit;
8. only then promotion eligibility.

Until those pass, repository status is `IMPLEMENTED_UNVERIFIED`.
