# Monolithize

Consume validated context, investigation graph, capability/adaptation decisions, provenance, and dependency graph. Build one coherent perfected-system representation; do not concatenate disconnected research notes.

Inspect the full agentic-system ontology: architecture, infrastructure, runtimes, interfaces, agent roles, governance, routing, skills/tools/MCPs/APIs, workflows/state machines, schemas/config, context/memory/retrieval, provenance/canonical precedence, ledgers/registries/graphs, research/execution, testing/evaluation, observability/debugging, permissions/secrets/security, lifecycle/versioning, release/CI/rollback, scheduling/automations, human approvals, cost/context controls, learning/promotion/deprecation, maintenance/handoffs, and inherited project/business/design constraints.

Create only artifacts with a defined machine/agent/human purpose. Typical outputs include `ideal-blueprint.md`, `ideal-functions.md`, `north-star.md`, `architecture.md`, `governance.md`, `roadmap.md`, `bootstrapping.md`, `agents.md`, `automations.md`, and `automations-schedule.md`, plus machine-readable graphs/schemas where structure improves determinism.

Run adversarial completeness review before handoff. Any material contradiction, unknown dependency, missing owner, or unverifiable requirement returns to `/investigate`; otherwise hand the coherent model to `/idealize`.
